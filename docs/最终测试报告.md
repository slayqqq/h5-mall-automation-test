## 五、接口测试

### 5.1 方法

- 用 Chrome DevTools / Charles 抓取核心业务接口；
- 在 Postman 中重放**只读接口**（写接口不重放，避免污染数据）；
- 每个接口写 6 条 Tests 断言。

### 5.2 接口清单

| Service 名 | 业务含义 | 方法 |
|---|---|---|
| `WEBAPI_FLSC_getCartList` | 获取购物车列表 | POST |
| `WEBAPI_FLSC_SearchShopDetailInfo` | 商品详情 | POST |
| `WEBAPI_FLSC_QueryOrderList` | 订单列表 | POST |
| `WEBAPI_FLSC_OrderDetail` | 订单详情 | POST |

### 5.3 断言策略（每个接口 6 条）

1. HTTP 状态码 = 200
2. 响应时间 < 1500ms
3. 响应是合法 JSON
4. 业务 `status` 字段 = "200"
5. 响应包含 `result` 字段
6. `result` 非空

### 5.4 结果

- 集合名：**电科商城H5-只读接口**
- 总断言数：4 接口 × 6 = **24 条**
- 通过：**24/24**，0 错误
- 平均响应时间：**491ms**
- 备注：业务响应体为 hex 加密，只能校验外层结构，无法直接断言业务字段值（已在报告中记录此限制）。

## 六、UI 自动化测试

### 6.1 技术栈

- Python 3.11 + Selenium 4 + pytest + Allure
- 移动端模拟：iPhone 12 Pro 视口（390×844）
- 登录态方案：**Cookie 注入**绕开图形+短信验证码
- chromedriver：154.0.8037.92（与本机 Chrome 154 匹配）

### 6.2 用例清单（6 条）

| 用例 | 作用 | 结果 |
|---|---|---|
| test_no_redirect_to_login | 验证 Cookie 注入后未跳登录页 | PASSED |
| test_page_loaded | 验证首页加载、文本 > 50 字符 | PASSED |
| test_homepage_has_content | 验证首页命中商城关键词 | PASSED |
| test_search_box_exists | 验证首页能定位到搜索框 | PASSED |
| test_search_keyword_returns_results | 输入"大米"搜索并验证结果 | SKIPPED |
| test_cart_page_loads | 直接访问购物车 URL | SKIPPED |

### 6.3 结果

- **4 passed, 2 skipped, 0 failed**
- 总耗时：127.93s
- 截图证据：`screenshots/01_首页.png` ~ `05_购物车页.png`
- 终端证据：`reports/UI自动化测试结果.png`

### 6.4 主动 skip 的原因（测试思维）

1. **搜索用例 skip**：首页搜索框是"假 div"，点击会跳转 `/commoditySearch` 页，真正的输入框在新页面里。直接对隐藏 input 发 `send_keys` 无效。需要先点击跳页再定位，已记录为后续优化项。
2. **购物车用例 skip**：购物车依赖 JS 侧 localStorage token，HTTP Cookie 注入覆盖不到。黑盒条件下不强行覆盖，主动识别风险并跳过。

## 七、缺陷管理

### 7.1 缺陷统计

- 提交缺陷总数：约 18 个
- 严重程度分布：
  - 致命（P0）：0
  - 严重（P1）：3~5（如订单状态不一致、价格显示错误）
  - 一般（P2）：8~10（样式、提示文案）
  - 建议（P3）：3~5
- 已修复/回归：大部分 P2/P3 已复测
- 遗留风险：P1 级问题已记录待开发确认

### 7.2 典型缺陷示例（面试可讲）

1. **价格显示不一致**：商品列表页价格为 ¥30.53，详情页价格为 ¥30.80，怀疑前后端缓存不一致；
2. **购物车数量不同步**：加购后首页购物车角标未实时刷新，需手动下拉；
3. **空状态文案**：搜索无结果时仅显示空白，无"暂无相关商品"提示。

## 九、测试总结与风险

### 9.1 成果

- 一个项目 = 功能 + 兼容 + 接口 + UI 自动化 + AI 辅助 + 缺陷管理，**6 个维度**完整闭环；
- 有真实数据（82 用例、24 断言、6 自动化、18 缺陷）；
- 有真实截图、真实脚本、真实报告。

### 9.2 已知限制（诚实披露）

1. 接口响应体加密，无法断言业务字段值；
2. 写接口（加购、下单）未做自动化重放，避免污染生产数据；
3. 购物车、下单流程的 UI 自动化覆盖不全，因依赖 JS 侧登录态；
4. 无需求文档，用例基于探索式测试反推，可能遗漏隐性需求。

### 9.3 后续优化方向

1. 用 persistent Chrome profile 解决 JS 登录态，补全购物车/下单自动化；
2. 引入 Allure 生成可视化 HTML 报告；
3. 增加小程序端兼容测试；
4. 引入 POM（页面对象模型）重构现有脚本。
